# 原生多模态 MM-DiT 与视频/音频 VAE 调研

> 调研日期：2026-10-06。仅采用公开资料（Hugging Face 模型卡、arXiv 论文、NVIDIA Cosmos 官方资料等）。**未查到的数字明确标注"未公开"，不做推测。**

## 0. TL;DR：两条原生多模态技术路线

| 路线 | 代表系统 | 核心思想 | 跨模态耦合位置 |
|---|---|---|---|
| **单流 packed MM-DiT** | MiniMax-H3（33B dense） | 文/图/视/音 latent 打包进同一条 token 序列，一个 Transformer 联合预测视频+音频 latent | 全程共享自注意力；模态差异只在输入/输出层与模态专属 AdaLN |
| **非对称双流 MM-DiT** | LTX-2 / LTX-2.3 / LTX-2.5（22B，视频流 14B + 音频流 5B） | 视频、音频各走一条宽度不同的流，通过**双向音视频交叉注意力 + 跨模态 AdaLN** 交换信息 | 每层块内的 AV cross-attention，仅用时间维 RoPE 对齐 |

两者都使用**模态解耦的 VAE**（视频、音频各自的 latent 空间），没有强行共用一个 latent；同步靠**共享物理时间轴上的位置编码**保证，而不是靠 token 排列顺序。

## 1. MiniMax-H3（MiniMax，2025-09 开源权重）

来源：HF 模型卡 `MiniMaxAI/MiniMax-H3`。

### 1.1 系统组成

- **H3-Context-IR**：托管式多模态指令理解/编排模块（解析、跨模态关联、时序理解），**未随权重开源**，仅提供 API。
- **H3-Base**：生成 768p 视频 + 立体声，开源（33B）。
- **H3-Regenerate-2K**：把 768p 结果连同原始上下文回灌，重生成 2K。

### 1.2 潜空间规格

| VAE | 通道 | 空间压缩 | 时间压缩 | 输入/输出 | 备注 |
|---|---|---|---|---|---|
| **H3-VisualVAE** | **24** | **16×** | **4×**（记法 `f16t4d24`） | 视频 24 fps | 时序因果 VAE；进 Transformer 前再做 `1×2×2` patchify，故**入 Transformer 的 token 等效空间下采样 32×、时间仍 4×** |
| **H3-AudioVAE** | 未公开（模型卡未写通道数） | — | **32 kHz 波形 → 40 Hz latent 序列**（每 token 25 ms） | 32 kHz 立体声 | 左右声道**共用同一套编解码器权重、但独立处理**，解码后再合并 |

- VisualVAE 额外做了 latent-space 优化（提升重建质量 + 可学习性）；编码器训练后，**另训了一个 ViT 解码器**降低解码成本、提升质量。
- AudioVAE 灵感来自 VA-VAE，同样做了 latent 空间优化。

### 1.3 联合去噪机制（H3-Omni-Transformer）

- **33B 参数 dense 单流 Transformer**；其中约 **13B 参数位于 AdaLN 相关分支**。AdaLN 调制输出可预计算/缓存，纯推理部署时这部分不必加载（官方完整权重全部发布）。
- 文本由 **H3-Encoder（完整使用 Qwen3-VL-32B 预训练权重，取第 50 层隐状态）**编码；视觉输入同时经 H3-Encoder 与 H3-VisualVAE 编码；音频只经 H3-AudioVAE。
- 所有表征组织成**统一 packed 多模态序列**，进入同一个 Transformer，**联合预测视频与音频 latent**。
- **注意力层和 FFN 层不含任何模态专属结构**；模态专属参数仅限于：输入/输出层、模态专属 AdaLN 分支。
- 条件侧有 **Token Refiner**（社区实现/模型结构资料：约 2 层带自注意力的 transformer，Qwen3-VL 输出先经它重组上下文再进 DiT；**不接触噪声 latent、不做去噪**——此细节来自社区对开源结构的描述，官方模型卡只概述了编码流程）。
- 原生支持**稀疏注意力**训练/推理以应对长序列；**首个开源版本只提供全注意力推理**，稀疏注意力代码后续发布。

### 1.4 统一位置编码：三轴 MM-RoPE 与多速率时间网格（重点）

- 使用**三维多模态旋转位置编码 MM-RoPE**，坐标为 `(t, h, w)`。
- **视频和音频映射到同一条物理时间轴**：
  - 视频：24 fps → 时间坐标每帧推进 1（在物理时间单位下）；经 VAE 4× 时间压缩后视频 latent 网格为 **6 Hz**。
  - 音频：latent 为 **40 Hz**，即每秒 40 个时间位置。
  - 换算到"每源视频帧"的尺度：每帧时长 1/24 s，对应音频时间坐标推进 40/24 = **5/3**。于是两条网格都是同一连续时间轴上的规则采样，RoPE 用（含分数的）连续坐标对各自 token 编码，注意力天然按物理时间对齐；在每 3 帧（1/8 s）边界上音频与视频网格整数对齐。（该 5/3 推导来自对开源实现的解读，如 X 上的结构分析；官方模型卡明确给出的是 24 fps、视频 VAE 4×、音频 40 Hz 这三个原始数字。）
  - **左右声道共享同一时间坐标，用另一根轴的不同位置区分声道**，从而既保持同步又保留声道身份。
- **物理时间由 RoPE 坐标定义，不由 packed 序列中的行顺序定义**——这是多模态打包可行的关键。

### 1.5 实测数字与局限

- 能力：输出 **2K、最长 15 s、24 fps、32 kHz 立体声**；Ref2VA 模式支持 ≤9 图 / ≤3 段视频 / ≤3 段音频 / 混合共 ≤12 个文件；稳定支持 11 种语言对白。
- 第三方评测（arXiv:2609.18323，非官方）考察了 H3 在多视角空间推理、音频消歧、视频决策推理、音视频综合推理等物理世界任务上的表现——属学术评估，具体分数见该论文。
- 官方模型卡**未公布** PSNR/VBench/人工胜率等常规对比数字（除引用第三方排名性表述外）。
- **局限**：Context-IR 不开源（影响完整复现官方效果）；开源初版无稀疏注意力；2K 需二次重生成流程；模型卡未给出音频 VAE 通道数等规格。

## 2. LTX-2 / LTX-2.3 / LTX-2.5（Lightricks）

论文：arXiv:2601.03233《LTX-2: Efficient Joint Audio-Visual Foundation Model》（2026-01-06）。

### 2.1 架构：非对称双流 DiT

- **视频流 14B + 音频流 5B（总 19B；论文正文数字）**。产品化的 LTX-2.3 / 2.5 标称为 **22B**（权重文件名 `22b`）；增量参数的具体分配官方未披露。
- 每个双流块顺序执行四步：**模态内自注意力 → 文本交叉注意力 → 音视频交叉注意力 → FFN**，块内穿插 RMSNorm。
- **双向 AV cross-attention**：视频 query ↔ 音频 K/V，对称反向；Q 与 (K,V) 先经各自时间步条件的 AdaLN 调制；交叉注意力**只施加时间维 1D RoPE**，强制跨模态交互只按时间同步、不按空间对齐。
- **跨模态 AdaLN 门控**：一条流的 scale/shift 参数以另一条流的隐状态为条件——论文明确指出这是为**两条流扩散时间步或时间分辨率不同**时的同步而设计。
- 两条流**共享同一去噪时间表**（shared timestep schedule）。
- 视频流用 **3D RoPE (x, y, t)**；音频流用 **1D 时间 RoPE**。
- **Modality-CFG（模态感知 CFG）**：引导式预测在标准文本引导项之外增加跨模态引导项，s_t 与 s_m 可独立调。论文设定：视频流 s_t=3, s_m=3；音频流 s_t=7, s_m=3。

### 2.2 潜空间规格

| 模态 | VAE | 通道/维度 | 空间压缩 | 时间压缩/帧率 |
|---|---|---|---|---|
| 视频 | LTX Conv Video VAE（因果） | **128** | **32×32** | **8×**；输出 24 fps（帧约束 8n+1） |
| 音频（LTX-2/2.3） | 因果 Audio VAE，输入为双通道 mel 频谱（波形先重采样到 **16 kHz**，逐声道算 mel 后通道维拼接） | **每 token 128 维** | — | **每 token ≈ 1/25 s → 25 Hz latent** |
| 音频还原 | 改造版 HiFi-GAN 声码器（双通道、生成器通道数相对 V1 翻倍） | — | — | latent 在 16 kHz mel 空间，声码器上采样输出 **24 kHz 立体声**波形 |

- 视频 VAE 总压缩 32×32×8，pixel→token 比 8192:1，patchify 已做进 VAE，Transformer 侧不再 patchify（LTX-Video 起的设计，arXiv:2501.00103）。
- 据 GitHub issue（Lightricks/LTX-2#275），**LTX-2.5 的视频/音频编码器、音频解码器与 2.3 逐字节相同，仅视频解码器更换为扩散解码器**；官方 2.5 模型卡称其为"new diffusion video decoder，取代 VAE 重建阶段"。

### 2.3 多速率时间网格如何统一（重点）

- LTX 的做法是**不统一网格、只统一时间轴**：视频 token（3D，24fps/8≈3 Hz latent 时间网格）与音频 token（1D，25 Hz）长度不同、维度不同，各自保留模态最自然的网格与位置编码（3D vs 1D）。
- 统一发生在三处：
  1. **交叉注意力只用时间维 RoPE**：Q/K 的时间坐标都以秒为连续物理时间，RoPE 内插分数位置，跨模态注意力按真实时间软对齐，无需重采样成同一 token 数；
  2. **跨模态 AdaLN** 让一条流按另一条流的隐状态/时间步做调制，处理分辨率与噪声水平差异；
  3. **共享去噪时间步表**：双流每一步同时去噪，对齐的是"去噪进程 + 物理时间"，而不是 token 网格。
- 论文称由此可学到唇形、环境混响等亚帧级对应关系（交叉注意力图可视化支持该说法）。

### 2.4 LTX-2.5 的增量（官方模型卡）

- **Diffusion Fidelity Rendering（DFR）**：不再对整片锁定单一压缩率；在 8× 时间压缩空间先搭运动/结构，同时按场景复杂度与算力预算生成高保真关键帧，再由专门扩散渲染阶段补细节。
- **新扩散视频解码器**：替代 VAE 重建阶段，改善人脸/纹理/屏内文字、快运动伪影。
- **原生多镜头**：单次输出跨切镜保持人物/场景/光线/语音/风格一致（此前仅单镜头）。
- 文本侧换成定制 **Gemma 4 12B** + prompt enhancer；可选 **duration predictor**；蒸馏版固定 8 步；提供 NVFP4/int8 量化版。
- 宣传支持 4K HDR / RAW EXR 工作流（属产品宣称）。

### 2.5 实测数字与局限

- 速度（论文 Table 1，H100，121 帧 720p，单步 Euler、CFG=1）：**LTX-2（19B，音+视频）1.22 s/step；Wan 2.2-14B（仅视频）22.30 s/step → 约 18× 快**。
- 视频纯视觉：Artificial Analysis（2025-11-06）图生视频第 3、文生视频第 4，超过 Wan 2.2-14B 等。
- 时长：论文称可生成 **20 s** 同步音视频（对比 Veo 3 的 12 s、Sora 2 的 16 s、Ovi/Wan 2.5 的 10 s）。媒体报道 2.5 生成 10 s 片段约需 6.8 s。
- 音视频质量：论文给出的是**内部人工偏好**结论（显著优于 Ovi，与 Veo 3 / Sora 2 可比），**未公开具体胜率数值或第三方客观指标**。
- **局限（论文自陈）**：低资源语言语音弱；多人说话时可能张冠李戴；超过约 20 s 出现时序漂移/失同步；无显式推理/世界建模能力。此外 25 Hz 音频 latent + 24 kHz 声码器上限意味着音频频响不及 32 kHz 直编方案；22B 相对 19B 的参数分配未披露。

## 3. 跨 VAE latent 翻译适配器：H3-to-LTX Latent Adapter

来源：HF 模型卡 `Efficient-Large-Model/H3-to-LTX-Latent-Adapter`（NVIDIA 的 Efficient Large Model 团队账号，配合 NVlabs/Sana 中的 Sol-H3-Spark 使用）。

| 项目 | 规格 |
|---|---|
| 用途 | 把**归一化后的 MiniMax-H3 视频 latent** 翻译成**归一化后的 LTX-2.5 Conv VideoVAE latent**，使 H3 主干可复用 LTX 侧（高压缩 128 通道）解码/上采样链路 |
| 输入 | `[B, 24, T_h3, H/16, W/16]`（H3：24 通道、空间 16×） |
| 输出 | `[B, 128, T_ltx, H/32, W/32]`（LTX：128 通道、空间 32×） |
| 结构 | **Conv3D 残差适配器，194,759,504 参数（约 195M）**，宽度 752，22 个 block；外加官方发布的时空 packing 变换；BF16 权重 389,541,112 字节 |
| 约束 | 必须把原始像素帧数与几何传入 `convert`；packing/归一化变换与 checkpoint 绑定，不可互换；适配器本身不含 H3/LTX 权重、不能单独生成视频 |
| 训练/质量数字 | **模型卡未公布**任何重建指标；社区反馈其预期用途是接 LTX latent upscale，而非直接 LTX VAE 解码（Reddit 讨论，非官方结论） |

意义：这是"**异构 VAE 不重训生成主干即可互通**"的实证——通道数（24→128）、空间网格（16→32）、时间网格（H3 4× vs LTX 8×）之间的映射全部由一个 ~0.2B 的 Conv3D 网络学习，时间网格差异通过 packing 变换 + 卷积残差适配吸收。局限是仅单向（H3→LTX）、仅视频、几何契约严格、无公开质量数据。

## 4. 参照系：Wan VAE 与 Cosmos Tokenizer

### 4.1 Wan VAE（阿里 Wan-Video）

| VAE | 通道 | 空间压缩 | 时间压缩 | patchify 后总压缩 | 使用模型 |
|---|---|---|---|---|---|
| **Wan2.1-VAE**（因果 3D VAE，127M 解码器） | **16** | **8×8** | **4×**（`1+T→1+T/4`，首帧单独走空间分支，滚动缓存） | 8×8×4 ×2×2 patch = **256×** | Wan2.1/2.2 T2V、I2V、S2V、Animate（14B MoE，27B 总参） |
| **Wan2.2-VAE** | 未在公开资料中明确（TI2V 模型侧） | **16×16** | **4×** | **4096×**（2×2 patch） | WanTI2V-5B dense，主打 24GB 卡跑 720p@24fps |

- 注意 8×8×4=256 已含 patch 说法在不同二手资料中口径不一；官方 Wan 论文（arXiv:2503.20314）的原始表述建议直接核对。上表 DeepWiki 数据为二手整理。
- Wan 本身**无原生音频生成流**（Wan-S2V 是 wav2vec2 音频条件驱动视频，不是联合出音频）。

### 4.2 NVIDIA Cosmos Tokenizer（视频/图像，连续 CV 与离散 DV）

- 轻量、时序因果（因果时间卷积 + 因果时间注意力），编码器起于两级 Haar 小波（时空各 4×）；连续版用普通 AE，离散版用 FSQ。
- **latent 维度 16**；空间压缩 8 或 16，时间压缩 4 或 8，总压缩最高 8×16×16 = 2048×。
- 重建指标（官方表，DAVIS / TokenBench）：

| 配置 | DAVIS PSNR / SSIM / rFVD | TokenBench PSNR / SSIM / rFVD |
|---|---|---|
| CV 4×8×8（105M，720×1280 编码 34.8 ms） | 32.80 / 0.900 / 15.93 | 35.45 / 0.928 / 6.85 |
| CV 8×8×8 | 30.61 / 0.856 / 30.16 | 34.44 / 0.917 / 11.62 |
| CV 8×16×16 | 27.60 / 0.779 / 93.82 | 31.61 / 0.875 / 43.08 |
| DV 4×8×8（FSQ） | 32.98 / 0.818 / 37.36 | 35.13 / 0.887 / 19.67 |

- Cosmos 是**tokenizer 套件，不含联合多模态生成主干**；定位世界模型基座。

## 6. 结论：多速率时间网格的两种统一范式

1. **H3 式：坐标统一，网格不统一。** 一个 Transformer、一条 packed 序列，但给每个 token 打连续物理时间坐标（MM-RoPE）。40 Hz 音频网格与 24 fps（VAE 后 6 Hz）视频网格通过分数坐标共存于同一时间轴，每 1/8 s 自然重合；左右声道再占用一根轴。优点是跨模态交互走全自注意力、最充分；代价是序列长、需要稀疏注意力。
2. **LTX 式：流不统一，时间轴与去噪进程统一。** 模态各留最自然的网格（视频 3D/约 3 Hz latent，音频 1D/25 Hz），交叉注意力只用时间 RoPE 做软对齐，跨模态 AdaLN 处理分辨率/时间步差异，共享噪声日程。优点是容量按信息密度分配、原生支持 V2A/A2V 编辑；代价是跨模态信息流受限于交叉注意力。
3. **当 VAE 本身不兼容时（H3 24ch/16× ↔ LTX 128ch/32×，时间压缩 4×↔8×）**，可用 ~0.2B Conv3D 残差适配器 + 确定性 packing 直接学习网格/通道翻译，不必重训主干——但目前仅有单向视频的实例且缺乏公开质量数据。
