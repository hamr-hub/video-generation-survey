# 02 · 音画同步机制

核心区分：是"音画一起凭空生成（联合）"，还是"一路条件驱动另一路"，还是"生成后对齐"。同步质量依次降低。

## 2.1 联合扩散（Joint Diffusion）——最强

**代表：MM-Diffusion（CVPR'23，微软）**

- 两条并行 UNet：视频子网 + 音频子网（非 DiT）。
- 两条 latent 在**时间维对齐成同一时间网格**：一段视频切成 T 个时间块，音频也切 T 块，块 t 对块 t。
- 每步去噪两条 UNet **互相 cross-attention**：画面决定动作时看到当前节奏 latent，音频生成时看到动作 latent。
- **joint shifted window（随机偏移窗口）**：强迫学习"动作→声音"的对应，而非各跑各。
- 结果：重拍自然落在大动作/落脚帧，同步在去噪轨迹中涌现。

**现代版本：MiniMax-H3 / LTX-2.3**——视频 token 与立体声音频 token 在同一条 DiT 流同一批去噪步里联合决定（不是后期配音）。

## 2.2 同步对齐的"拍子"是什么

本质是对齐**运动能量曲线 ↔ 音频能量包络**（训练数据本身已对齐，如 AIST++）。

| 画面侧 | 音频侧 |
|---|---|
| 动作速度峰值（手/脚/身体） | 节拍 onset、鼓点 |
| 大幅动作帧 | 重拍、低频能量峰 |
| 静止/留白 | 音乐停顿、呼吸 |
| 舞蹈速度/风格 | BPM、曲风 |

物理因果越强的场景（跳舞、打鼓、踩地、演奏）同步越自然。这解释了为何小模型在"音乐+舞蹈"能成，却做不了自由对白。

## 2.3 条件生成（单向同步）

| 方向 | 输入→输出 | 代表 |
|---|---|---|
| 音频→画面 | 音乐/语音逐时刻注入条件，画面卡拍生成 | Syncphony、音频驱动舞蹈 |
| 画面→音频 | 视觉/动作特征为条件生成音效 | Diff-Foley |
| 音频→对嘴 | 语音驱动唇形 | LatentSync/MuseTalk/EchoMimic/Hallo |

对齐靠"喂进去的对方特征时刻"，比联合涌现更"硬"，时间条件外部给定。

## 2.4 H3 的音频位置编码（工程要点）

- 音频 40Hz token，视频 24fps，速率不同。
- 用**三轴位置坐标**：时间轴 + 立体声（左右）轴 + 模态轴。
- 左右声道共享时间坐标，但在声道轴上取不同位置。
- Qwen3-VL 表征先过两层 Token Refiner 再进 DiT。

## 2.5 后处理对齐（最弱）

生成完用 Syncformer 等检测音画偏移再拉伸音频。只能纠偏，无法让"动作踩点"。不推荐作为主同步手段。

## 2.6 小结

- 要**原生同步质量**：联合扩散（H3/LTX 单流；MM-Diffusion 双 UNet）。
- 要**轻量+可控同步**：条件驱动，或两段式（小模型锁节拍）。
- 时间网格对齐是所有方案的共同工程难点：按**物理帧位置**对齐，而非张量下标。
